# EpisyHub — React Native / Expo

Первый рабочий этап Android-приложения. Это отдельный проект: зависимости сайта и приложения устанавливаются независимо.

## Реализовано

- Вход в существующий аккаунт по почте и паролю; на Android токен хранится в Expo SecureStore.
- Главная, библиотека с четырьмя статусами, поиск **в своей библиотеке**, карточка с прогрессом и списком серий.
- Отметка следующей серии / фильма и отмена через существующий серверный API с проверкой ревизии.
- Календарь сохранённых дат на ближайшие 30 дней; профиль и отзыв сессии при выходе.
- Обновление списка жестом и при возвращении в приложение, ошибки сети, истёкшая сессия и системная кнопка «Назад» Android.
- Цвета текущей тёмной темы и иконка из существующего брендинга сайта.

## Запуск

Из каталога `mobile`:

```bash
npm ci
cp .env.example .env.local
npm start
```

В `.env.local` укажите `EXPO_PUBLIC_API_URL` — origin сервера **с этими изменениями**, без `/api` и без завершающего пути. По умолчанию используется `https://episyhub.space`; пока сервер не обновлён, мобильный вход там недоступен. Переменная публичная: в неё нельзя помещать пароли, DATABASE_URL и ключи API.

Для локального Next.js запустите его из корня репозитория, например `npm run dev -- --hostname 0.0.0.0`. На физическом Android укажите доступный телефону LAN-адрес компьютера. `localhost` телефона не указывает на компьютер. HTTP разрешён клиентом только в dev-режиме; релиз требует HTTPS. Доступность HTTP в конкретной Android-сборке зависит от её сетевой конфигурации; для проверки на устройстве предпочтителен HTTPS-сервер.

Откройте проект в совместимом Expo Go либо development build. Expo SDK 58 и версии зависимостей зафиксированы lock-файлом. В период перехода на SDK 58 обычный Expo Go из магазина может поддерживать только SDK 57; для этого проекта используйте совместимую сборку Expo Go или development build.

```bash
npm run typecheck
npm run lint
npx expo-doctor
npx expo export --platform android
```

`npm run test:ui` из `mobile/` запускает браузерный сценарий против настоящих Next.js и локальной PostgreSQL в отдельной временной схеме. Нужны зависимости корневого проекта, локальный `TEST_DATABASE_URL` / `DATABASE_URL` и Chromium (`CHROMIUM_PATH`, по умолчанию `/usr/bin/chromium`). HTTP-мост в тесте воспроизводит нативные запросы без CORS и не подменяет данные API. Скриншоты сохраняются в `test-results/`.

`npm run web` — дополнительный браузерный просмотр. На web сессия хранится только в памяти. Веб-просмотр с другого origin требует отдельного same-origin прокси к API; сервер намеренно не открывает CORS для токенов. Нативный Android не использует браузерный CORS.

## Android-сборки

`eas.json` содержит профиль `preview` для APK и `production` для AAB. Перед первой облачной сборкой требуется войти в собственный аккаунт Expo, связать EAS-проект и подтвердить постоянный Android package (`space.episyhub.app`). Идентификатор опубликованного приложения потом менять нельзя.

```bash
npx eas-cli@latest login
npx eas-cli@latest build:configure
npx eas-cli@latest build --platform android --profile preview
npx eas-cli@latest build --platform android --profile production
```

URL сервера задайте также в окружении соответствующего профиля EAS. Облачная сборка, подпись, загрузка в Google Play и публикация в рамках этого этапа не выполнялись.

## Серверный контракт

`POST /api/mobile/session` принимает `{ email, password }`, возвращает `{ token, expiresAt, user }`. `GET` проверяет сессию, `DELETE` отзывает её. Защищённые запросы используют `Authorization: Bearer …`.

Токен — случайные 256 бит. В существующей таблице `Session` хранится только SHA-256 в пространстве `mobile:`. Сайт продолжает использовать JWT Auth.js. Миграция базы не нужна. Сессия действует 30 дней, после этого нужен повторный вход; автоматического продления в первой версии нет. Смена passwordHash немедленно делает прежние мобильные сессии недействительными при следующем запросе. Явный недействительный Authorization никогда не подменяется браузерной cookie-сессией. Вход ограничен счётчиками PostgreSQL по почте и источнику запроса.

Мобильные сессии поддержаны общими `getCurrentUser` / `getCurrentUserId`: библиотека, прогресс, профиль и календарь используют их. Маршруты с прямым `auth()` не становятся автоматически доступными мобильному клиенту. На данном этапе они приложению не требуются.

## Перед первым APK

Профили EAS явно используют `https://episyhub.space` и соответствующее окружение `preview` / `production`. До запуска компиляции `eas-build-pre-install` проверяет публичный `/api/mobile/session`: ожидается JSON-ответ 401 без авторизации. Если на рабочем сайте API ещё не развёрнут или адрес закрыт Vercel Authentication, сборка останавливается с понятной причиной. Никакие пароли или тестовые записи для проверки не нужны.

```bash
EXPO_PUBLIC_API_URL=https://episyhub.space npm run check:api
npx eas-cli@latest login --device
npx eas-cli@latest init
npx eas-cli@latest build --platform android --profile preview
```

Вход `--device` подтверждается в личном браузере; пароль не передаётся в чат. Для продолжения удалённого входа может понадобиться число, показанное Expo. Проект связан с Expo: `@episyhub.space/episyhub`, ID `d2b76d33-403a-4d5c-ac15-b6c597bb422f`; владелец и project ID сохранены в `app.json`. Временные `_vercel_share`-ссылки и секреты обхода защиты в APK не встраиваются.
