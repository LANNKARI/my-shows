# EpisyHub Android 0.3.0

Реализованы одобренные мобильные экраны без замены сайта и без миграций базы.

- На главной постер сохраняет формат 2:3 и показывается целиком рядом с названием. Для крупного постера используется TMDB w342, для маленьких — w185.
- Трекер группирует серии по сезонам. Каждый сезон можно свернуть, есть «Свернуть всё». Кружок меняет просмотр; отдельная стрелка раскрывает детали серии. Список остаётся виртуализированным, очередь отметок из 0.2.2 сохранена.
- Оценка тайтла и каждой серии: 1–10, изменение и удаление через существующий owner-scoped ratings API. Пока рейтинг сохраняется, связанные изменения прогресса ждут завершения сверки серверной ревизии, чтобы не получить устаревший quick-progress.
- Вместо истории/поиска библиотеки — «Что посмотреть» с рулеткой и подборкой, фильтрами типа, жанров, минимального рейтинга, года и исключения анимации, карточкой результата и добавлением в планы. Старый `/search` перенаправляет на `/discover`. До запуска подбора нет списка всех сохранённых тайтлов.
- Профиль содержит отдельную вкладку достижений; шестерёнка открывает настройки, карандаш аватара — выбор изображения. Настройки включают имя, описание и аватар.
- Аватар выбирается из системной фотогалереи (без запроса камеры и микрофона), на Android доступно квадратное кадрирование. Загрузка — multipart `/api/upload`, затем PATCH `/api/users/me`; JSON Content-Type не подставляется для FormData.
- Экспорт сохраняет только библиотечные поля исходного формата v2: meta, userShows и collections, включая прогресс, оценки и заметки. Приватный профиль, список друзей и комментарии в файл библиотеки не включаются. На Android используется системное меню сохранения/отправки файла с отдельным именем для каждой выгрузки, в web-preview — загрузка JSON.
- Импорт JSON ограничен существующим API до 2 МБ: выбор файла → предпросмотр → сопоставления → повторная проверка → явное подтверждение. Выбор соответствий накапливается локально, чтобы не создавать отдельную серверную задачу для каждой строки. Существующие записи не перезаписываются. Продолжение идёт по серверному cursor; после ошибки повтор допустим по идемпотентному протоколу jobId/cursor. Повреждённый JSON отклоняется до обращения к серверу. После окончания можно выбрать файл заново и начать новый проход.
- Смена пароля требует текущий пароль и повтор нового. При подтверждённом успехе пароль удаляется из состояния формы и завершается мобильная сессия; новый вход проверяется отдельно. Библиотечные действия в настройках ждут завершения уже запущенных отметок.

## Исправление общего API

Регрессионный тест воспроизвёл ошибку `/api/wishlist`: при совпадении внешнего ID у фильма и сериала выбор сериала мог добавлять фильм. Поиск существующей карточки теперь учитывает и media type. Создание планов по-прежнему не меняет статус уже сохранённой записи. Данных и схемы исправление не меняет.

## Проверка

- Mobile TypeScript и ESLint, root TypeScript, ESLint изменённого API.
- Expo Doctor: 20/20 (для сетевых проверок в среде запуска нужен `NODE_USE_ENV_PROXY=1`).
- 13 тестов существующего кэша/очереди.
- Полный React Native Web → реальный Next.js → изолированная PostgreSQL: прежние быстрые отметки/offline/409, независимое сворачивание сезонов, оценки тайтла/серий и удаление, рулетка/подборка/фильтры/планы, multipart аватар, вкладка достижений, экспорт JSON, отклонение плохого файла, импорт новой записи с сохранением старого прогресса, смена пароля и вход с новым паролем, социальные функции и изоляция аккаунтов.
- Только внешние TMDB и Cloudinary заменены провайдерами-фикстурами в дочернем тестовом процессе. API приложения и операции PostgreSQL не подменяются. Прелоадер включается только при `MOBILE_UI_UPSTREAM_FIXTURES=1`.
- Серверный набор расширен регрессионным случаем одинакового TMDB ID у фильма и сериала.

Нативные системные окна выбора фото/файла, кадрирование и сохранение через Android share sheet требуют проверки APK на физическом телефоне. Web-проверка не заменяет эти действия на устройстве.

Результат проверок: TypeScript и ESLint прошли; Expo Doctor 20/20; кэш/очередь 13/13; серверный набор 111/111. Итоговый сквозной прогон включает также добавление фильма и сериала с одинаковым TMDB ID в разные карточки и вход с новым паролем.
