# Регистрация с подтверждением почты

Новая регистрация сохраняет заявку на 24 часа; профиль, вход и приветственные 100 🍿 доступны после подтверждения адреса. Существующие аккаунты входят как раньше: эта миграция не объявляет их адреса подтверждёнными и не блокирует их.

Ссылка одноразовая, содержит случайный 256-битный токен. В базе хранится SHA-256 токена и bcrypt-хеш пароля. Токен находится во фрагменте URL, не передаётся при GET страницы; страница убирает его из адресной строки. Подтверждение выполняется только кнопкой и POST, поэтому предпросмотр письма не создаёт профиль. Повторная отправка меняет токен; если отправка завершилась ошибкой, предыдущая ссылка сохраняется. Неподтверждённая заявка не меняет существующие учётные записи.

Ограничения хранятся в PostgreSQL и действуют между экземплярами Vercel: регистрация — 8 запросов за 15 минут с одного адреса, повторная отправка — 15 за 15 минут, подтверждение — 30 за 15 минут. На адрес почты — максимум 5 запросов отправки в час и минимум минута между отправленными письмами. Вне Vercel сервер использует общий локальный лимит вместо доверия произвольному X-Forwarded-For. Истёкшие заявки и лимиты очищаются при новой регистрации. После очистки истёкшей заявки нужно зарегистрироваться снова.

## Выкладка

1. Сделать свежий бэкап рабочей Supabase.
2. В SQL Editor рабочей базы целиком выполнить `prisma/migrations/20261101000000_email_verification/migration.sql`, от BEGIN до COMMIT. Не выполнять повторно после успешного завершения.
3. Проверить:

```sql
SELECT c.relname, c.relrowsecurity
FROM pg_class c JOIN pg_namespace n ON n.oid=c.relnamespace
WHERE n.nspname='public' AND c.relname IN ('PendingRegistration','AuthRateLimit');
```

Должны быть две строки, обе с `relrowsecurity = true`. Миграция добавляет две закрытые таблицы, не изменяет User или существующие сохранения.

4. В Vercel → Settings → Environment Variables установить для Production:

| Name | Value |
| --- | --- |
| `UNISENDER_GO_API_KEY` | API-ключ сервера go2, пометить Sensitive |
| `EMAIL_FROM` | `noreply@episyhub.space` |
| `EMAIL_FROM_NAME` | `EpisyHub` |
| `APP_URL` | `https://episyhub.space` |

Адрес API по умолчанию — `https://go2.unisender.ru/ru/transactional/api/v1/email/send.json`, по подтверждённому пользователем датацентру. Для другого датацентра допускается `UNISENDER_GO_API_URL` с тем же путём на go1 или go2. Ключи не добавлять в GitHub, чат или переменные NEXT_PUBLIC. AUTH_SECRET, DATABASE_URL и пулер менять не нужно.

5. Для проверки Preview задать те же почтовые переменные в окружении Preview и `APP_URL` равным точному HTTPS-адресу этой Preview-сборки, чтобы письмо возвращало на неё. После изменения переменных пересобрать Preview. Если Preview защищена Vercel, для проверки письма потребуется войти в Vercel.
6. Проверить старый вход; новую регистрацию; отсутствие доступа до подтверждения; письмо и папку «Спам»; кнопку подтверждения; вход и 100 🍿 после подтверждения; повторное открытие ссылки без повторной награды. Проверить ошибочную/истёкшую ссылку и повторную отправку.
7. Объединить PR в main, дождаться Ready / Production. Проверить полный сценарий на рабочем домене новым тестовым адресом. Только после этого включать регистрацию публично в объявлениях.

Если письмо не пришло, проверить домен/DKIM и журнал доставки в go2. Принятие письма API не гарантирует доставку в конкретный почтовый ящик. Код не повторяет отправку автоматически после неопределённого результата.

## Изменения просмотра

Отметка и снятие отметок сезона выполняются одним нажатием, без второго подтверждения. Успешная отметка серии не создаёт текстовое уведомление и не прокручивает страницу. Компактная кнопка отмены остаётся доступной; ошибки сохранения видимы. Если последняя серия удаляет нажатую кнопку из DOM, фокус переходит на отмену без прокрутки для доступности с клавиатуры.

## Проверка реализации

Автоматические тесты используют отдельную локальную схему PostgreSQL и локальный имитатор почтового API, не отправляют настоящие письма. Проверяют миграцию и RLS, запрет входа до подтверждения, конкурентное использование ссылки, истечение срока, ротацию токена, cooldown и лимиты, восстановление после почтовых ошибок. Реальная отправка через аккаунт пользователя проверяется на Preview/Production после настройки Vercel.

VK ID, Яндекс ID и восстановление забытого пароля не входят в этот PR.

## Отказы Unisender и бесплатный тариф

По официальной документации бесплатный тариф ограничивает отправку своими доменами и заранее подтверждёнными адресами (код API 903). Успешное системное письмо себе и подтверждение домена отправителя не означают, что разрешена отправка на произвольные адреса новых пользователей. Для публичной регистрации нужен соответствующий тариф или другой отправщик без этого ограничения.

На форме показывается безопасный код поддержки MAIL-903 и аналогичные коды. В Vercel Logs записываются только HTTP-статус, числовой код API и заранее заданная категория причины. Сырые ответы провайдера, адреса получателей, пароли, токены и ключи не записываются. MAIL-102 означает неправильный ключ или датацентр; MAIL-105 — API выключен; MAIL-206 — домен отправителя не подтверждён; MAIL-215 — аккаунту запрещена отправка; MAIL-902 — дневной лимит бесплатного тарифа; MAIL-904/905 — ограничение оплаты/тарифа; MAIL-NETWORK — соединение или таймаут.

Аутентификация Unisender поддерживает и X-API-KEY, и поле api_key. Код использует заголовок; смена этого способа сама по себе не снимает тарифных ограничений.
