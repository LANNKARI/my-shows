# Оформление за попкорн

Магазин `/cosmetics` доступен из меню аккаунта, профиля и страницы наград. Примерка не меняет профиль и баланс. Покупка навсегда добавляет предмет в личную коллекцию; кнопка «Применить» выбирает его отдельно. Рамка и оформление обложки занимают независимые слоты. Стандартное оформление бесплатно. Загруженная личная обложка сохраняется и возвращается при выборе стандартного оформления.

| Предмет | Цена, 🍿 |
| --- | ---: |
| Розовый неон | 80 |
| Золотая | 120 |
| Киноплёнка | 100 |
| Лунный свет | 100 |
| Звёздная пыль | 160 |
| Винный акцент | 140 |
| Кинозал | 180 |

Рамки видны в профиле, меню аккаунта и комментариях. Оформление обложки меняет верхнюю часть профиля. Общие темы сайта и расширенная статистика отложены.

## Покупки и безопасность

Каталог и цены определяет сервер. Перед покупкой пользователь подтверждает стоимость и остаток. Списание и запись покупки выполняются одной транзакцией с блокировкой строки пользователя. Повторный запрос за уже купленный предмет не списывает баланс; чужая покупка не даёт право применить предмет. При изменившейся цене требуется обновить магазин. Если ответ потерян, кнопка обновления проверяет коллекцию перед повторной попыткой.

Таблица `CosmeticPurchase` закрыта RLS без публичных политик; доступ осуществляется через авторизованный сервер. Публичные ответы содержат выбранное оформление, но не историю покупок и баланс. Данные оформления сессии обновляются из базы, а не из присланного клиентом объекта.

Ежедневная награда и счётчик ответов викторины используют условное атомарное обновление, чтобы параллельные запросы не выдавали повторные награды. Дневная граница — UTC; лимит викторины — 10 попыток. Это не полная защита викторины от читов: отдельные серверные состояния игровых раундов здесь не вводились.

## Выкладка в Supabase и Vercel

Рабочая база этими изменениями автоматически не обновляется. Сначала выполните миграцию, затем проверяйте Preview и объединяйте PR.

1. Сделайте резервную копию схемы `public` со структурой и данными через pgAdmin. Убедитесь, что процесс имеет статус Finished, файл существует и не пуст. Надёжная проверка резервной копии — восстановление в отдельную тестовую базу.
2. Откройте Supabase → SQL Editor рабочего проекта. Скопируйте **целиком** файл [migration.sql](../prisma/migrations/20261027000000_popcorn_cosmetics/migration.sql), включая BEGIN и COMMIT, и выполните один раз. Скрипт добавляет два столбца User и таблицу покупок; баланс, обложки и прогресс не изменяет. Если возникает ошибка, сохраните её текст; не запускайте отдельные фрагменты повторно.
3. Проверьте результат отдельными запросами:

```sql
SELECT column_name, data_type, column_default
FROM information_schema.columns
WHERE table_schema = 'public' AND table_name = 'User'
  AND column_name IN ('avatarFrame', 'profileStyle');

SELECT relrowsecurity
FROM pg_class
WHERE oid = 'public."CosmeticPurchase"'::regclass;
```

Первый запрос должен вернуть два текстовых столбца со стандартными значениями; второй — `true`.

4. Проверьте, что Preview Vercel подключён к нужной базе Supabase. Не публикуйте строки подключения и пароли. Откройте Preview: проверьте вход, старые сохранения и баланс, примерку и отмену. Купите один предмет, примените и обновите страницу; проверьте профиль и комментарии. Повторное применение не должно списывать попкорн.
5. После проверки объедините PR в `main`; дождитесь Ready / Production в Vercel и повторите проверку основных действий на сайте.

Если база ведётся через Prisma Migrate и SQL применён вручную, отдельно отметьте миграцию применённой командой `prisma migrate resolve --applied 20261027000000_popcorn_cosmetics` с корректным подключением. Не запускайте `migrate reset` и `db push --accept-data-loss` на рабочей базе.

## Проверки

- 56 проверок API с настоящей локальной PostgreSQL в изолированной временной схеме: авторизация, серверные цены, параллельные покупки, откат списания, владение, сессии, награды и сохранность прежних данных при миграции.
- 69 браузерных проверок Chromium, включая магазин на ширинах 320, 390 и 1440 px; браузерные API подменяются фикстурами. Рабочая база и реальные аккаунты не используются.
- ESLint изменённых TypeScript-файлов и production-сборка `npm run build -- --webpack`.

В облачной среде Turbopack ограничен запуском CSS worker; сборка проверена через Webpack без изменения конфигурации Vercel. Safari и рабочий deployment автоматически не проверялись.
