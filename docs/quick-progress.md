# Быстрая отметка и отмена

В списке и постерах библиотеки добавлена кнопка «Отметить серию» для сериалов со статусом «Смотрю» и загруженной следующей неотмеченной серией. Для фильмов в статусах «Смотрю» и «В планах» доступно «Просмотрено». Сериалы без загруженных серий по-прежнему открываются через трекер; быстрая отметка не делает внешних запросов TMDB.

После подтверждённого ответа сервера обновляются прогресс, таймкод и счётчики вкладок. Завершённый тайтл переходит в «Просмотрено». Обычная отмена размещается прямо в карточке и не перекрывает её действия. Если запись исчезла из текущей вкладки, сообщение с кнопкой «Отменить» остаётся доступным отдельно над мобильной панелью. Пока запрос сохраняется, все быстрые действия блокируются, а выбранная кнопка показывает загрузку. Старое состояние не заменяется неподтверждённым оптимистическим результатом.

Отмена восстанавливает прежние watched, watchedAt, stoppedAt, статус и флаг завершения. Если строка EpisodeProgress была создана быстрой отметкой, отмена удаляет только её. Фильм без строк эпизодов отмечается через существующий статус без создания общих эпизодов каталога. Старые озвучка, избранное, оценки и другие поля не изменяются.

## Серверные гарантии

`POST /api/user-shows/<UserShow.id>/quick-progress` проверяет сессию и владельца. Отметка принимает время обновления снимка и ожидаемый ID следующей серии; сервер сам определяет текущую серию. Изменения выполняются в Serializable-транзакции с блокировкой записи UserShow. Устаревшие, повторные и конфликтующие запросы отклоняются с HTTP 409. Повторное действие не переходит незаметно к следующей серии.

Для отмены сервер выдаёт подписанный HMAC-токен, ограниченный владельцем, записью и 10 минутами. Используется существующий AUTH_SECRET, новая переменная или миграция не нужна. Токен хранится только в памяти текущего экрана, не в URL/localStorage; после ухода со страницы или перезагрузки кнопка отмены не восстанавливается. Доступна отмена последнего успешного быстрого действия. Предыдущие действия можно изменить вручную в трекере.

Перед отменой сервер проверяет отпечаток текущей записи и всего её прогресса. Более поздние правки (в том числе старым трекером без обновления родительского updatedAt) делают отмену недоступной. После отмены revision обновляется монотонно, а не возвращается к старой дате, поэтому повторное использование токена не срабатывает. Подпись отделена от других токенов приложения отдельным контекстом.

Последняя серия завершает сериал только если отмечены все известные эпизоды и их количество покрывает объявленное общее число. Исторические ссылки на эпизоды другого тайтла не учитываются при завершении.

HTTP-ошибка не меняет показанный прогресс. При сетевом обрыве после возможного коммита нельзя достоверно утверждать, что запрос не сохранён: интерфейс предлагает обновить библиотеку перед повтором. После ошибки отмены сохранённая отметка остаётся до подтверждённого восстановления. Ротация AUTH_SECRET делает старые токены отмены недействительными, не меняя сами записи.

## Проверки

`npm run test:security` использует временную схему локальной PostgreSQL и реальные Credentials-сессии. Проверяются права, повторные/параллельные запросы, восстановление таймкода, завершение последней серии, фильмы с эпизодами и без них, неполный каталог, конфликт с последующими изменениями, подпись и срок действия отмены.

`npm run build` и `npm run test:ui` проверяют production-сборку. UI-тесты используют подставленные API, а не рабочую Supabase: отметка и отмена, двойной клик, ошибки сохранения/отмены, исчезнувшая после завершения строка и режим постеров.

Рабочие данные при подготовке не изменяются. Перед объединением PR миграция не требуется. После деплоя нужно проверить одну отметку и её отмену на своём аккаунте.

Проверено: 26 API/security-тестов и 27 браузерных тестов прошли без пропусков; production-сборка и TypeScript прошли, ESLint изменённых компонентов и нового API прошёл. Проверены допустимый same-origin запрос и запрет чужого Origin, а также видимость отметки/отмены после перестановки строки сортировкой. На физическом iPhone/Safari и в рабочей Supabase эти проверки не выполнялись.
