# Карточка тайтла и трекер

Обновлены `/show/[id]` и `/library/[id]` по согласованным макетам. Новые колонки, таблицы, переменные окружения и миграции не нужны.

## Карточка

- Компактный постер на телефоне, основные действия рядом с названием, отдельные подписи TMDB и «Моя оценка».
- Статус, избранное, оценка, озвучка и место просмотра сохраняются через существующий PATCH по **Show.id**. Изменение оценки, избранного или заметки сохраняет текущий статус. Первое такое действие добавляет отсутствующий тайтл в планы.
- Значения меняются после подтверждения сервера. Во время запроса повторные действия блокируются; при ошибке заметки остаются в редакторе. Запрос сохранения ограничен 15 секундами.
- Информация, актёры и обсуждение доступны отдельными кнопками. Переключение разделов не размонтирует обсуждение и не теряет его черновик.
- Трейлер открывается в портале над страницей: фокус остаётся в окне, Escape закрывает его и возвращает фокус на кнопку.
- Гость может читать карточку; действия с личной библиотекой предлагают вход.

## Трекер

- Текущая серия и её время остановки видны над сезонами. Первая непросмотренная серия определяется в порядке сезона и номера эпизода; фильм в трекере сохраняет прежнюю модель одной части.
- Быстрая отметка использует существующий POST по **UserShow.id** с проверкой `updatedAt` и ожидаемой серии. Отмена использует тот же подписанный токен и ограничение 10 минут, что и библиотека. Она доступна на текущей странице до обновления/ухода или следующего изменения; обновление страницы удаляет уведомление, сохраняя прогресс. После завершения последней серии фокус переходит на отмену.
- Смена статуса, заметок и оценки сохраняется через существующий PATCH по **Show.id**. Ручные отметки отдельных серий, сезона и времени используют существующий POST по **Show.id**; для них новая отмена не добавлялась. Успешное ручное изменение закрывает уведомление об отмене предыдущей быстрой отметки.
- Массовая отметка/снятие отметок сезона требует явного подтверждения. Время проверяется как ММ:СС или ЧЧ:ММ:СС; пустое значение удаляет таймкод.
- При открытии развёрнут только первый незавершённый сезон (либо первый, если завершены все). Показано до пяти серий вокруг текущей; весь список можно раскрыть. Сохранение времени и отметок не сворачивает открытые сезоны.
- На телефоне настройки свёрнуты, на компьютере находятся под постером. HTTP(S)-адрес места просмотра открывается безопасной внешней ссылкой; обычное название остаётся текстом.
- Трекер сбрасывается при смене пользователя, гостю личные данные не показываются.
- GET трекера дополнен актуальной ревизией записи и `originalTitle`; личная оценка выбирается только среди оценок всего тайтла. Счётчик исключает старые записи прогресса, ссылающиеся на серии другого тайтла.
- Существующее поведение GET трекера сохранено: при первом открытии он может добавить запись в «Смотрю» и подтянуть список серий из TMDB. Изменения интерфейса не превращают этот старый маршрут в API только для чтения.

## Проверки

- Production-сборка: `npm run build -- --webpack`; встроенная проверка TypeScript прошла.
- ESLint изменённых компонентов, API и UI-тестов прошёл.
- `npm run test:ui`: 41 тест, включая 14 новых сценариев карточки/трекера и проверки ширин 320, 390 и 1440 px, ошибок сохранения, гостя, отмены, подтверждения сезона, времени и клавиатуры.
- `npm run test:security`: 27 тестов с настоящими сессиями и отдельной временной схемой локального PostgreSQL. Рабочая Supabase не используется.
- Обычная сборка через Turbopack в этой среде блокируется при открытии служебного порта обработчика CSS (`Operation not permitted`). Для локальной проверки использован поддерживаемый Next.js вариант `--webpack`; команда сборки проекта и настройки Vercel не менялись.
- Браузерные проверки выполнены в Chromium с подставными API-ответами и демонстрационными данными. Это не проверка реальных аккаунтов, TMDB, YouTube или Safari/iPhone.

## Выкладка

1. Открыть preview PR в Vercel и проверить свой тайтл: оценку, заметки, отметку серии и отмену, таймкод и подтверждение сезона.
2. Объединить PR в `main`; Vercel запустит production deployment.
3. После статуса Ready проверить те же действия на основном домене. При необходимости откатить deployment средствами Vercel — схема БД не менялась.
