# Восстановление загрузки аккаунта

## Подтверждённые дефекты

`getCurrentUser()` перехватывал ошибки базы и возвращал `null`. API библиотеки и наград отвечали 401 даже при корректной сессии, если запрос к PostgreSQL завершался ошибкой. Меню при этом использует JWT и продолжало показывать пользователя. Теперь ошибка базы не подменяет отсутствие сессии; библиотека и награды возвращают 503 с запретом кеширования и общим сообщением без внутренних подробностей.

Страница наград после неуспешного запроса отображала нулевой баланс, нулевую серию и состояние «сегодня уже получено». Теперь она показывает ошибку и кнопку повторной загрузки. Подтверждённый баланс не заменяется нулём при сбое.

Чтение библиотеки и баланса имеет таймаут 8 секунд на попытку и не более одного автоматического повтора при сетевой ошибке, таймауте или ответе 5xx. Ответы 401/403 не повторяются. При уходе из библиотеки запрос отменяется. Покупки, ежедневные награды и изменения прогресса автоматически не повторяются.

Проверка существования пользователя для получения ID запрашивает только ID вместо полного профиля. Пул Prisma ограничен тремя соединениями на экземпляр; ожидание свободного соединения и подключение — по 8 секунд. Явно заданные параметры DATABASE_URL имеют приоритет. Это ограничение уменьшает риск исчерпания подключений, но не доказывает, что причиной задержек на рабочем сайте был пул.

## Выкладка

Новая миграция не требуется. После проверки Preview объедините PR и дождитесь Ready / Production. Войдите в существующий аккаунт, откройте библиотеку и награды, проверьте баланс и старый прогресс. При временной ошибке используйте «Повторить загрузку», а не многократное обновление страницы.

Для Vercel с Supabase проверьте, что runtime-переменная DATABASE_URL использует рекомендованное Supabase подключение Transaction pooler (обычно порт 6543). Session pooler на 5432 оставьте для pgAdmin/бэкапа при необходимости. Строку нужно копировать из Connect текущего проекта с правильными hostname, пользователем и настройками Prisma — не менять только номер порта вслепую. Пароль и строку подключения не публикуйте. Для CLI-миграций используйте подходящее прямое/сессионное подключение отдельно.

Точная причина задержек production пока не подтверждена: доступа к авторизованному браузеру пользователя и рабочим метрикам PostgreSQL нет. Если задержки остаются, в DevTools → Network измерьте `/api/auth/session`, `/api/popcorn` и `/api/user-shows?status=library`: HTTP-статус и время ожидания ответа (TTFB). Перед передачей скриншота скройте Cookie, токены и Authorization. Сопоставьте время с Vercel Logs и метриками подключений Supabase. Успешный, но долгий запрос может не появиться в фильтре ошибок.

## Проверка

57 API-тестов на изолированной локальной PostgreSQL, включая реальный сбой доступа к таблице пользователей: корректная сессия получает 503 вместо 401 и восстанавливается после возвращения таблицы. Браузерные проверки включают автоматическое восстановление библиотеки и отсутствие ложного нулевого баланса. Production-сборка Webpack и ESLint изменённых файлов проходят. Production-база и переменные Vercel не изменялись.
