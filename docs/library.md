# Обновлённая библиотека

Экран `/watching` объединяет четыре вкладки: «Смотрю», «В планах», «Просмотрено», «Брошено». Мобильная панель и верхнее меню открывают этот экран; верхняя ссылка «Хочу посмотреть» ведёт сразу на вкладку планов. Старые `/wishlist` и `/planned` сохранены со своими рекомендациями и действиями, чтобы не ломать существующие ссылки.

Доступны список и постеры, поиск по названию и оригинальному названию, фильтр типа тайтла и сортировки по обновлению, названию, личной оценке. Фильтры и вид записаны в query-параметры `status`, `q`, `type`, `sort`, `view`: они сохраняются после обновления страницы и при переходах между вкладками. Поиск не отправляет отдельные запросы на каждый символ.

Личная оценка берётся из оценки тайтла без episodeId. Рейтинг TMDB и оценки отдельных серий не подменяют её. В строках видны текущие отметки, первая неотмеченная серия по порядку сезонов/эпизодов и сохранённый таймкод. Отсутствующее число серий не выдаётся за ноль процентов или завершённый просмотр. Статус «Просмотрено» сам по себе не создаёт отметок серий.

Карточки ведут на существующие `/show/<Show.id>?type=...` и `/library/<Show.id>`, используя внутренний ID каталога вместо смешивания с UserShow ID и TMDB ID. Кнопки быстрой отметки серии и отмены относятся к следующему этапу.

## API и данные

Добавлен `GET /api/user-shows?status=library`: он возвращает только записи текущего пользователя, включая dropped, и не запускает прежнюю синхронизацию TMDB при чтении. Схема базы и записи пользователей не меняются, миграция не нужна. Остальные режимы API сохранены: `status=all` по-прежнему исключает dropped. Недопустимые статусы возвращают 400. В ответ добавлено отдельное поле `userRating`.

Клиент загружает один снимок своей библиотеки, фильтрует его локально, отменяет запрос при уходе со страницы/смене сессии и не сохраняет пользовательские списки в localStorage. Ошибка сети, пустой список и отсутствие авторизации показываются отдельно. Событие `user-shows-updated` обновляет снимок.

## Проверка

```bash
npm run build
npm run test:ui
npm run test:security
```

UI-тестам нужен Chromium (инструкция в `docs/mobile-navigation.md`); при наличии системного браузера задайте `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`. Данные и API в UI-тестах подставлены. Они проверяют все статусы, личные/серийные оценки, поиск, фильтры, сортировки, восстановление URL и Back, прогресс/таймкоды, отсутствие запросов записи и адаптивность 320–1440px.

Security-тесты используют отдельную временную схему локальной PostgreSQL. Новая проверка подтверждает owner scope, включение dropped, личную оценку, отсутствие изменений записи при чтении и сохранение поведения старого `status=all`. Рабочая Supabase не используется.

Проверено при подготовке изменения: production-сборка и TypeScript прошли; 17 UI-тестов и 17 проверок API/безопасности прошли без пропусков. ESLint нового экрана, вспомогательного модуля и UI-тестов прошёл. Реальные TMDB, Supabase и устройства Safari этими локальными проверками не проверялись.
