# Android-приложение EpisyHub: этап 1

## Архитектура

`mobile/` — независимое Expo-приложение на TypeScript с Expo Router. Маршруты находятся в `mobile/src/app/`, карточка открывается в стеке, нижняя панель переключает разделы. Оно использует существующие Next.js API и PostgreSQL, не подключается к базе напрямую. Next.js tsconfig и ESLint исключают мобильный проект, у которого собственные версии React / TypeScript.

В этом этапе не меняются экраны сайта и схема базы. Добавлен `/api/mobile/session` и поддержка явных bearer-токенов в общих функциях определения пользователя. Обычный запрос без Authorization по-прежнему использует Auth.js. Запрос с любым явным недействительным Authorization получает отказ, даже если содержит действующие cookies.

## Проверяемый сценарий

Вход в мобильное приложение → загрузка своей библиотеки → отметка следующей серии → транзакция существующего quick-progress API → обновлённая библиотека. Результат доступен сайту через ту же базу. Старая ревизия даёт 409, чужая запись — 404. Отмена использует серверный ограниченный по времени undo-токен. Сетевые ошибки сохранения не вызывают автоматический повтор мутации.

Сессия имеет фиксированный срок 30 дней. Пароль не сохраняется на телефоне; токен сохраняется в SecureStore. Выход сначала отзывает токен на сервере и затем очищает устройство. Если сервер недоступен, приложение сообщает об ошибке и сохраняет текущий вход, чтобы не объявлять удалённую сессию отозванной. При смене пароля проверка версии passwordHash отклоняет старые мобильные сессии.

Релиз клиента принимает только HTTPS-origin API. В server Session лежит хеш токена с префиксом mobile:. Повторный вход создаёт отдельную сессию устройства. Существующая таблица Session уже есть в миграциях, дополнительных миграций не требуется.

## Проверки

- `npm run test:security` — добавлен реальный интеграционный сценарий мобильного входа, сохранения/отмены прогресса, изоляции владельцев, истечения, отзыва и смены пароля. Нужна локальная PostgreSQL; тестовый harness создаёт отдельную схему и удаляет её после завершения.
- Корень: `npx tsc --noEmit`.
- `mobile/`: `npm run typecheck`, `npx expo-doctor`, `npx expo export --platform android`.
- Для устройства и публикации см. `mobile/README.md`.

Для ограниченных по памяти окружений harness поддерживает `TEST_NEXT_WEBPACK=1`; проверка сервера выполнялась с этим флагом и `NODE_OPTIONS=--max-old-space-size=2048`. Исправлены две старые зависимости между тестами: удаление общего bob-пользователя и исчерпание owner-квоты промокодов теперь выполняются на отдельных аккаунтах.

## Результат проверки 2026-11-08

- TypeScript сайта — успешно.
- ESLint новых серверных файлов и затронутого API библиотеки — успешно.
- `mobile/`: ESLint и TypeScript — успешно.
- Expo Doctor — 20/20.
- Expo export Android — успешно, Hermes bundle; это не APK/AAB и не нативная сборка.
- Серверные security integration tests на отдельной локальной PostgreSQL — 110/110 с Webpack и лимитом памяти Node, указанными выше.
- `mobile/tests/e2e.cjs` после подключения Expo Router — успешно: ошибочный и успешный вход, библиотека, сохранение и отмена серии с проверкой PostgreSQL, конфликт 409 после отдельного изменения базы, восстановление после конфликта, поиск, календарь, ошибка офлайн-выхода и успешный отзыв сессии. Необработанных ошибок браузера нет. Браузерный мост воспроизводит нативные HTTP-запросы; он не проверяет Android SecureStore и системную навигацию.
- Проверки выполнены на тестовых данных. Развёртывание серверного API, EAS-проект, подписанный APK/AAB, физическое устройство и публикация в Google Play остаются следующими этапами.
